# 模块 1 — L2 架构约束

---

## ARC-01: 纯 USB 连接

**决策**: 仅支持 USB 有线连接，不支持 WiFi/网络 ADB。

**理由**: 用户明确需求。减少连接管理的复杂度（无需处理IP配置、网络发现、断线重连），代码更简单可靠。

---

## ARC-02: subprocess 封装 ADB

**决策**: 通过 Python `subprocess` 模块调用宿主机 `adb` 命令行工具，不做 ADB 协议级实现。

**理由**: ADB 协议实现复杂且无必要。`adb` 客户端是标准工具，Windows 平台广泛可用。封装命令行调用即可满足所有操作需求。

---

## ARC-03: 单次递归扫描

**决策**: `list_files` 使用 `adb shell find <path> -type f` 一次性获取完整文件列表，再用 `stat` 批量获取属性。

**理由**: 避免多次 `adb shell ls` 递归调用的开销。一次命令完成遍历，减少 ADB 通信往返次数。7000 文件量级下 `find` 命令执行时间 < 3 秒。

---

## ARC-04: 阻塞式同步调用

**决策**: 所有 ADB 操作使用阻塞式调用，无异步、无线程池。

**理由**:
- ADB 本身不支持并发操作单个设备
- 照片下载瓶颈在 USB 带宽，不在 Python 侧
- 阻塞式代码简单、可调试、错误定位直接

---

## ARC-05: 超时与重试策略

**决策**: ADB 命令统一 30s 超时，最多重试 1 次。超时和重试在模块1内部处理，对调用方透明。

**理由**:
- 30s 足以完成 `adb pull` 大多数文件（单文件 < 100MB 场景）
- 重试 1 次可覆盖偶发的 USB 通信抖动
- 2 次失败说明存在持续性问题（线缆松动、设备休眠），继续重试无意义
